mail-transport fixtures (synthetic; no real mailbox data)

gmail-transcript.imap   Server side of one IMAP session modelled on Gmail's documented
                        responses (Gimap greeting, CAPABILITY, "authenticated (Success)",
                        EXAMINE with UIDVALIDITY/UIDNEXT/HIGHESTMODSEQ + [READ-ONLY],
                        UID SEARCH, UID FETCH with HEADER.FIELDS literals, BODY[]<0>
                        partial fetch, AUTHENTICATIONFAILED / app-password ALERT, BYE).
dovecot-transcript.imap Same for a Dovecot-style server (CAPABILITY in the greeting and
                        LOGIN code, a multi-literal FETCH with FLAGS/MODSEQ interleaved,
                        an unsolicited FLAGS-only FETCH, EXPUNGE, ID, NO, BAD, "+").
alert-biorxiv.eml       Minimal alert message (text/plain). Its body contains "{5}" so the
                        framer is shown not to scan literal content.
advisor-request.eml     Minimal person message (text/plain) with a lone ")" body line.

All files use CRLF line endings; literal counts {n} are exact byte counts. The
transcripts were generated by a small script that embeds the two .eml files (header
fields filtered like a server's HEADER.FIELDS reply); nothing was recorded from a real
server or mailbox. If you regenerate them, keep CRLF and recompute every {n}.
